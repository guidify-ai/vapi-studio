# Vapi Studio 0.1.1 — Writing the rules down

- **Status:** Released 2026-09-25 — *Retrospective, written 2026-10-25 from commits*
- **Previous published version:** 0.1.0
- **Breaking:** no

## Where we were

0.1.0 made Studio a public package, but its principles lived in commit messages
and the maintainer's head. Contributors could not tell which changes the project
would accept or why the code was shaped as it was. Apps installed Nest peers at
whatever version resolved, and new developers did not know which credentials
they needed before their first call.

## Announcement

0.1.1 writes the rules down. Studio now has a public constitution for the
framework, an Architecture Decision Record (ARD) workflow for pull requests, and
its first ARD. NestJS peer dependencies are pinned exactly, and a credentials
checklist covers Vapi, Twilio and the Brain provider.

## Features

### 1. Public constitution

**What:** SpecKit constitution scoped to the framework only — consumer bots and
commercial roadmaps out of scope.

**Why:** A public project needs written principles to review against; and the
earlier internal constitution mixed in product material that does not belong in
an open-source repo.

### 2. ARD workflow

**What:** PRs that change exports, Supervisor/Brain behaviour, persistence or
documented contracts add an ARD (context, decision, consequences, alternatives).

**Why:** Commits say what changed; ARDs say why, at the moment the decision is
made. Every later "why is it like this?" starts here.

### 3. ARD-0001: host-scoped ingress

**What:** The documented contract is `{PUBLIC_BASE_URL}/vapi/webhook` and
`/vapi/chat/completions`; UUID prefixes are a proxy concern.

**Why:** One app, one URL keeps setup simple and matches the npm README.

### 4. Exact Nest peer pins

**What:** Nest, TypeORM and RxJS peers pinned to exact versions.

**Why:** Floating peers meant two apps on the same Studio version could run
different framework behaviour.

### 5. Credentials checklist

**What:** One checklist for Vapi, Twilio and Brain keys.

**Why:** Missing credentials were the most common first-call failure.

## How 0.1.1 was tested

- **Automated:** unit tests.
- **Proof through projects:** projects built on Studio running real calls.

## Upgrade guide

Align your app's Nest / TypeORM / RxJS versions with the exact peers in
`package.json`.

## LinkedIn post

```text
Vapi Studio 0.1.1 shipped no new runtime features. It shipped rules.

A day after the framework became a public npm package, I realised its principles only existed in my head and in commit messages. A contributor couldn't tell what the project would accept, or why the code looked the way it did.

So 0.1.1 added a public constitution for the framework, and a lightweight Architecture Decision Record for every pull request that changes how the framework behaves. Commits tell you what changed. Decision records tell you why, written at the moment the decision is made, with the alternatives that lost.

It looked like paperwork at the time. Four releases later, those records are the reason I can explain every part of the framework, and they made the bigger 0.2.0 changes possible to reason about at all.
```
