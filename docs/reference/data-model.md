# Data model

Postgres persistence + in-memory runtime for Vapi Studio.

## Postgres tables

### `conversations`

| Column | Purpose |
| --- | --- |
| `id` | Framework conversation UUID |
| `status` | `ACTIVE`, `ENDED`, … |
| `metadata` | Channel, module, provider ids |
| `runtime_state` | Checkpoint JSON for crash recovery |
| `final_state` | Snapshot at end |

### `conversation_events`

Durable subset from `EventService.persist` — lifecycle, `ROUTE_DECISION`, `FORM_SENDOUT`, app events.

### `provider_ingress`

Raw webhook and Custom LLM request bodies for operator inspection.

### App tables

Applications may add their own TypeORM entities (e.g. caller profiles). Those belong in the **app repo**, not the framework.

## In-memory (per active call)

Not Postgres source of truth:

- Portal counters (`madStrikes`, still-there attempts)
- Listen registration state
- `CallTurnQueue` (utterance coalescing)
- Pending form exposes (until submit/timeout)

## Identity model

| Id | Role |
| --- | --- |
| `conversationId` | Canonical — generated by framework |
| Vapi `call.id` | Provider correlation only |
| `callerId` | App variable — cookie UUID (web) or ANI (phone) |

## Cross-call resume

`ConversationResumeService` — same `callerId` within ~10 minutes may clone prior ACTIVE/ENDED conversation into a new call.

## Crash recovery

On boot, `restoreAllActive()` reloads conversations with `runtime_state` into the registry. Single-process PoC — not distributed failover.
