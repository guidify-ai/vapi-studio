# Vapi Studio 0.0.1 — Deterministic voice agents, in code

- **Status:** Released 2026-09-06 (alpha) — *Retrospective, written 2026-10-25 from commits*
- **Previous published version:** none
- **Breaking:** n/a (first release)

## Where we were

Vapi assistants were configured as prompts and tools in a dashboard. A business
call flow — greet, qualify, collect a name and address, book, hand off — lived
inside one large prompt, and the model decided at every turn what happened next.
That is fine for open conversation and fragile for a business process: the same
caller input could take different paths, a prompt edit could break a step nobody
was looking at, and there was nothing to test or diff.

## Announcement

Vapi Studio is a NestJS toolkit for building **deterministic** voice agents on
Vapi. The call flow is code: typed steps (`AgentNode`), an explicit graph
(`flow.yaml`), and a Supervisor that routes each caller turn. An LLM is used
only where it is genuinely needed — at listen boundaries, to understand what the
caller meant — and the flow decides what happens next. 0.0.1 is an alpha:
usable, unstable, and published to show the approach.

## Features

### 1. Code-driven flow

**What:** Each conversational step is an `AgentNode` class: what to say, what to
listen for, what to do with the answer. `flow.yaml` declares the graph and which
intentions lead where. The Supervisor owns the turn loop.

**Why:** A business process has to behave the same way for the same input, be
covered by tests, and change through reviewed diffs. Code gives all three; a
dashboard prompt gives none.

**Trade-offs:** More upfront structure than a single prompt; open-ended chat is
not the goal.

### 2. Brain only at listen boundaries

**What:** The "Brain" scores which intention the caller expressed and extracts
fields, and only when a Node is listening.

**Why:** Speech understanding is where models are strong; deciding the business
path is where they are unpredictable. Splitting the two keeps the flow
deterministic while still accepting natural speech.

**Trade-offs:** Every intention must be declared; the model cannot invent paths.

### 3. Vapi adapter

**What:** Vapi's Custom LLM endpoint and webhooks are handled by an adapter; Nodes
see typed context, not Vapi payloads.

**Why:** Keep application code readable and absorb Vapi API changes in one place.

### 4. Flow Studio UI

**What:** An operator single-page app that renders the flow and conversation
forensics.

**Why:** A voice flow is hard to reason about from logs alone; operators need to
see the graph and the path a call took.

### 5. Agent handbook

**What:** Rules and references stamped for Claude and Cursor agents, including a
UI↔API identity doctrine.

**Why:** Much of the framework and its apps are written with coding agents; they
need the same conventions a human contributor would read.

### 6. Repo hygiene

**What:** Build output, dependencies and archives stopped being tracked; secrets
kept out of the tree.

**Why:** The repository was about to be public.

## How 0.0.1 was tested

- **Automated:** `node:test` unit tests, mocked Brain.
- **Manual:** calls through Vapi against the sample landing app.
- **Not recorded:** formal sign-off did not exist yet (see 0.2.0, ARD-0005).

## LinkedIn post

```text
The first version of Vapi Studio was born from one frustration: a business phone flow living inside a single giant prompt.

Greet, qualify, collect a name, book a visit, hand off to a human. In a prompt-only voice assistant, the model decides every next step. The same caller sentence could take a different path tomorrow, an innocent prompt edit could break a step nobody was watching, and there was nothing to unit-test or diff.

So I flipped it. In Vapi Studio the call flow is code: typed steps, an explicit graph, and a supervisor that routes every turn. The language model is used only where it is genuinely strong, understanding what the caller meant when they speak. What happens next is decided by the flow, not the model.

0.0.1 was an alpha, built in a week on NestJS and TypeScript, with a small operator UI to see the graph and the path each call took. Rough, but the core idea has survived every release since: models understand, code decides.

Full article: https://github.com/guidify-ai/vapi-studio/blob/master/docs/releases/v0.0.1.md
```
