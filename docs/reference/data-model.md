# Data model

Postgres persistence + in-memory runtime for Vapi Studio.

## Postgres tables

### `projects`

| Column | Purpose |
| --- | --- |
| `id` | Public ingress UUID — path segment in `/{projectUuid}/vapi/...` |
| `slug` | Stable short name (unique), e.g. `roofr-poc` |
| `name` | Display name |
| `created_at` | Audit |

Apps store a **fixed** UUID in `config/project.identity.json` and upsert it on every boot (`yarn start`) so local/dev Vapi URLs stay stable across re-seeds.

### `conversations`

| Column | Purpose |
| --- | --- |
| `id` | Framework conversation UUID |
| `project_id` | Owning project (ingress UUID) |
| `status` | `ACTIVE`, `ENDED`, … |
| `metadata` | Channel, module, provider ids |
| `runtime_state` | Checkpoint JSON for crash recovery |
| `final_state` | Snapshot at end |

Unique on `(project_id, provider_call_id)`.

### `conversation_events`

Durable subset from `EventService.persist` — lifecycle, `ROUTE_DECISION`, `FORM_SENDOUT`, app events.

`ConversationRepository.listRecent({ limit, offset })` — newest-first list for operator debug UIs.

### `provider_ingress`

Raw webhook and Custom LLM request bodies for operator inspection. Includes `project_id` when the request hit a project-scoped URL.

### App tables

Applications may add their own TypeORM entities (e.g. caller profiles). Those belong in the **app repo**, not the framework.

## In-memory (per active call)

Not Postgres source of truth:

- Portal counters (`madStrikes`, still-there attempts)
- Listen registration state
- `CallTurnQueue` (utterance coalescing)
- Pending form exposes (until submit/timeout)

## Identity model

| Id | Role |
| --- | --- |
| `projectId` | Public ingress — URL path; registered in `projects` |
| `conversationId` | Canonical — generated by framework |
| Vapi `call.id` | Provider correlation only |
| `callerId` | App variable — cookie UUID (web) or ANI (phone) |

Vapi `assistantId` is **not** used for project routing (forensics only).

## Cross-call resume (post-MVP)

`ConversationResumeService` — opt-in; same `callerId` within ~10 minutes may clone prior ACTIVE/ENDED conversation into a new call after caller confirmation.

## Crash recovery (post-MVP)

Opt-in: `restoreAllActive()` reloads conversations with `runtime_state` into the registry on boot. Not distributed failover.
